## 2. 核心科学问题与竞争解释

问题：只使用初始模型及它自己后续策略，不读取答案、测试反馈、奖励或外部教师，反复学习自己生成的代码时，能否提高正确率，同时保留多个尝试可覆盖的可解题目？

最强竞争解释：

1. 收益来自温度/截断改变了分布，而不是递归或新约束。
2. 收益来自软目标消除了局部标签采样噪声，完整软目标已经足够。
3. 收益只是步长变小、算术锚定、更多生成或参考前向。
4. 训练/评测题目重合、短输出截断、提取方式或不完整计分造成假象。
5. 改善只发生在一个随机种子或被反复查看的开发题目上。

KL、熵、Gini 和概率下限违反量仅解释分布变化。任务端点仍是官方 pass@1 和 pass@10。
pass@10 表示可解题目的采样覆盖，不能单独证明同一题存在更多语义不同的正确程序。
有限轮结果也不能声称无限递归稳定。

## 4. 对照必须在公式和实现上匹配

默认核心对照：初始模型、硬目标递归 SSD、完整软目标、算术锚定、固定第一轮数据继续训练，以及相同目标的低学习率版本。

本次源码审查识别出的缺口：

- 旧 lower_lr 的目标是 hard。M08/M10/M13 等需要的是 full_soft_lr_half，不能直接拿旧名字代替。
- 旧 fixed_alpha 是 (1-a)p+a·one_hot(y)。M05/M09 需要确定性 (1-a)p+a·mu；混入硬标签会引入额外噪声。
- M12 使用 SGD，因此必须与 SGD 的 full-soft、等范数缩步、算术锚定比较，不能把与 AdamW 的差异归因于投影。
- M03 需要 c=0 退化检查、同信息算术混合及公平调参；目标下限不等于学生模型的硬保证。
- M07 当前构造仍然是 dense；不能因用了“分层采样”就声称省显存或加速。
- M14 要控制题目权重；M15 要计入第二策略生成前向，并区分生成混合和目标锚定。

GKD 必须进入最近方法比较。设计为：
同一自身冻结轮次教师、同一有完整支持的目标 mu_eps=(1-0.02)mu+0.02*p_round，
比较 forward KL / reverse KL / JSD(beta=0.5)，并单独做按轮缓存 / 每次更新使用当前学生生成的 3×2 因子比较。
每轮同为 32 个提示、64 条序列、16 个梯度累积组；报告实际 token 与耗时。
未经平滑的截断目标含零，不能直接用有限数值裁剪冒充合法的 reverse KL 比较。
这些叫 **GKD 启发的同信息 self-policy 适配**，不是原论文额外监督教师设置的精确复现。
代码和评测未资格验证前，不能声称已战胜 GKD 或 CRISP。

15 个候选的必要对照、区别性预测与证伪条件见 [METHOD_MATRIX.md](METHOD_MATRIX.md)。
controls/ablations/seeds 不计为新 idea。共用基线只有在数据、模型、训练种子、轮次、配置、代码和计费方式都一致时才可复用。

## 5. 运行与统计设计

主模型固定 Qwen2.5-Coder-1.5B-Instruct；保持单基座 FP16 + FP32 LoRA、rank 16、同优化步数与每题平均目标。
训练仍用 T=1.5、top-k=20、top-p=0.8；明确改变这些量的 M04 等使用独立条件 ID，不能借用另一条件的基线。
训练上限 384 token 是现有起点；资格测量记录截断率。若需要改变上限，所有对应对照一起生成子协议，不能丢掉截断失败。

开发阶段 seed=17，只用于定位和选择，不能给 15 个方法发正式成功/失败判决。
每题 10 个评测样本支持官方 pass@10；同一组共享任务和预先生成的采样种子。
相比旧版每题 2 次，这是独立的 v2 设计，不能静默混合分母或预算。

确认阶段的候选上限是 2 个，只有完整开发对照后才选择：
先要求训练/测量有效及所有必需对照齐全；再按相对于最强合格简单基线的 pass@10 差值排序，
同时要求开发 pass@1 未出现超过 1 个百分点的下降；并列按实际训练耗时、再按既有候选排名。
未通过开发筛选的候选保留全部记录，不自动科学 KILL。

确认拟定独立训练 seeds=[23,47,71,101,131]，与开发 seed 分离。
这是有限重复计划，不是“五个种子天然足够”；确认前根据开发方差与实测成本审查精度。
若预算不足，保留 INCONCLUSIVE；不能改用最有利的种子或缩小必要对照。
超出原有 8 小时的部分只是规划，不自动获准执行。

估计量：先在每个任务内按官方规则计算，再在任务与训练重复上等权平均。
同题多个生成、同一模型的多个轮次都不算独立训练重复。
拟定交叉重采样 task ID 与 training seed（所有 arm/round 共用重采样索引），20,000 次、分析 seed=20261006。
原始 draws 保留在单元格内。报告任务条件不确定性和跨训练种子不确定性的范围。
对全部拟确认的候选×必要对比×端点×benchmark/model 先确定检验族，采用 Bonferroni 置信水平；
不得等结果出来后删除失败对比。自定义统计回放 adapter 尚需实现和审查，当前 runner 的单种子任务 bootstrap 不等价。

规划示例仅是精度计算：若配对二元结果不一致率为 0.1，32 题的正态近似 95% 半宽约 11 个百分点，
132 题约 5.4 个百分点；实际数值取决于测得的方差，不能用此例当实验结果。
因此旧 32 题设置不支持默认宣称 2 个百分点的小收益已被确认。
增加每题采样数主要减少解码噪声，不能把 32 题变成 320 个独立任务。

## 6. 提前规定判定，不看完结果再改

以下是待资格/精度审查后冻结的计划阈值，单位为原生指标的绝对百分点，不是已观察的效果。

**保留能力类候选：**

- 若声称自我提升：R3 pass@1 相对初始模型的改善至少 2pp。
- 若声称保留优于简单替代：R3 pass@10 相对每个必要简单替代改善至少 2pp，pass@1 非劣界为 -1pp。
- 对初始模型的 pass@10 非劣界为 -1pp；仅熵增加不满足要求。
- 区别性对照必须闭合。只打败 hard 而未打败 full-soft/相关简单替代，不支持新约束的必要性。
- 使用上述同时置信区间判断；不得只按点估计过线。

**效率类 M07：**
相对 full-soft，任务 pass@1/pass@10 的非劣界均为 -1pp；含必要额外前向的训练墙钟至少下降 10%。
生成、训练、评测、保存分别计时，总成本一并报告。单看某个张量核速度不构成效率证据。
分层与 iid 尾部对照需相同 head/draws/期望目标；局部方差定理不能替代原生任务与成本结果。

统一顺序：
1. 输出缺失、失败未记账、实现/基线/评分不合格、费用不可比、置信区间无效 → INCONCLUSIVE。
2. 完整有效证据的上界已排除必要效果，或证实必要约束违反 → 仅对该固定范围 KILL。
3. 任务收益成立但预先声明的可分离机制未获支持 → REVISE；新的假设需子协议与新确认。
4. 所有必要效果、机制与资源界限成立 → PASS，只支持该协议范围。
5. 其他 → INCONCLUSIVE。没有“弱 PASS”，OOM 也不直接算科学失败。

## 7. 一个 GPU、8 小时怎样安排

沿用用户在本会话指定的 1×RTX 2080 Ti、约 11GB、8 小时。
设备型号是用户陈述；当前空闲显存、驱动、占用、Conda 环境和实际吞吐仍需 GPU 主机读数。
首次意图时间为 2026-10-06 16:00 Europe/London；若确实按时开始，原硬截止为次日 00:00。
本聊天没有连接 GPU，不知道它是否已开始；不能把此刻修订当作重新获得 8 小时。

最新版 skill 要求 Conda 原生执行。EvalPlus **已经有官方 native Python 入口**，并非没有 Docker 就不能评测。
旧仓库把它包成了 Docker-only 调用。本次已修改 setup/preflight/scorer/cleanup/环境身份，原生官方两题参考检查通过；目标 GPU 主机仍需自己的环境与资格记录。
主机执行生成代码所需隔离能力须实际确认；Conda 仅管理依赖。不得生成新的容器启动方案。

建议收尾预留 15 分钟，资格/校准合计上限 60 分钟；这是限额，不是实测耗时承诺。
费用未知时只安排有明确上限的资格/校准；预期完成方法数保持 unknown。
计时/源码/协议变化创建新身份，不覆盖正在运行的输出，不自动延期。

完整成本公式与有限 inventory 见 resource-plan.json。
需要跨窗的比较保持同一科学身份；只有仍在原累计授权内才能继续。用完本次 8 小时并不授权另一个 8 小时。
